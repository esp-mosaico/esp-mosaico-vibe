# ESP-Iris 请求/结果与服务生命周期重构

此重构保持协议的 4000 B payload 上限，不合并文件任务。实际 TCP 连接
和 Recovery writer 的 RAM 上限不属于正常应用 25 KB 预算范围。

## 实现边界

- 执行器的工作对象改为 `iris_executor_work_t`，保存会话标识、独立请求
  和原始结果描述，不再分配 `iris_runtime_t` 或调用 wire-buffer 初始化。
- 主协议任务独占发送序号、COBS/CRC 编码和传输。慢任务不编码响应，
  主任务也不再解码已编码的完成响应。
- 输入容量为启用服务的最大请求：RPC 的 12 B 头加 body；OTA 的 BEGIN
  或 DATA；系统更新的完整 manifest/signature BEGIN 或 DATA，分别取最大值。
  输出容量为当前服务最大结果（RPC 的 12 B 头加 body），不随大 OTA chunk
  对称扩张。
- 输入和输出独立，RPC 回调直接写入结果缓冲的 body 区，没有注册状态中的
  独立 `rpc_response` 和完成后的响应体复制。
- 结果在 TX 忙时保持 DONE 和所有权，直到主任务编码成功；过期会话结果
  丢弃。断线/停止只发布 abandoned/cancel 意图，回调退出后由慢任务清理，
  不能提前释放正在使用的字节。
- 保留常驻执行器选项及通用配置的空闲释放机制；慢回调、Flash 写入和取消
  回调没有移回协议任务。PING、STATUS 和 job/system-update 状态仍有非阻塞
  控制路径。
- 正常低峰值配置保留任务及其请求/结果存储，避免旧任务栈尚未回收时重建
  第二份栈；空闲时不释放结果缓冲。通用非常驻配置按空闲超时回收执行器。
  RPC 注册本身不再触发结果缓冲分配。

## 服务生命周期

| 内容 | 分配/保留方式 |
| --- | --- |
| RPC 注册表、screen 后端、鉴权 token | 常驻小注册状态 |
| jobs 及终态 | 有界记录，保持 handle 地址和 ID 语义 |
| RPC 重放计数、鉴权挑战、重启计划 | 会话组，按需创建，断线/停止清理 |
| 截图控制、三个媒体槽 | 活跃媒体组，首次 OPEN/START 创建，最后一个流关闭后释放 |
| OTA handle、hash 和目标信息 | 通过 BEGIN 校验后创建，END/失败/取消/断线释放 |
| RPC 输出 | 执行器原始结果缓冲，不随注册分配 |

媒体发布者只增减 pin 计数，主协议任务回收空闲组，避免两个最后退出的
发布者竞争释放；即使流已关闭，仍在发布者使用期间也不能回收。无活跃组
时 credit 不解引用空指针，截图 CLOSE 和镜像 STOP 保持幂等。

会话创建、销毁及 RPC 重放校验由主协议任务负责；慢任务不保留会话指针，
旧请求的异步清理不能破坏重连后的新会话。会话按需创建时生成新鉴权挑战。

正常配置继续显式使用 PSRAM，分配失败不回退内部 RAM。
`ESP_IRIS_RPC_RESPONSE_PSRAM` 配置键保留，改为控制执行器结果存储；
`ESP_IRIS_SERVICE_CONTEXT_PSRAM` 控制请求上下文，并使结果也位于 PSRAM。
通用 writer 配置继续使用内部工作存储。

## 容量预算

容量随启用的服务和配置上限确定，不包含分配器管理开销。正常配置下：

- 执行器输入为 RPC 头与 1024 B body，输出为响应头与 1024 B body；
  不再保留两块 4 KiB wire buffer。
- 常驻注册信息不再附带独立的 1 KiB RPC 响应数组；会话和媒体控制组
  按各自生命周期分配。
- Recovery 使用 3968 B OTA chunk 时，请求容量相应扩大；结果仍按服务
  响应上限分配，不与输入统一采用最大 wire frame 容量。

这些工作存储在正常配置中原本已位于 PSRAM，因此容量精简不能直接称作
内部 RAM 节省。截图 shadow/capture 的 PSRAM 容量保持不变。内部 RAM
预算口径及产品边界见 [内部 RAM 预算](esp-iris-internal-budget.zh-CN.md)。
