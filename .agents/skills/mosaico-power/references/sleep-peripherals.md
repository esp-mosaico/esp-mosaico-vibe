# 睡眠外设与验证边界

用于 USB 唤醒、保留显示画面的 AOD 和触摸低功耗扫描。以下来自 **Review light sleep changes** 会话（`01a19c0d-7d58-7871-9095-d9706ca51af9`，核对至 2026-11-11）的实验与供应商信息，不是所有板型或当前工作区固件的能力声明。接入前复核目标 SDK、面板/触摸型号与实际源码。

## USB：主机恢复总线后才能通信

该轮已验证路径为：枚举完成 → 主机允许挂起且释放活跃 USB → MCU light sleep → 主机恢复总线 → 原设备醒来并重建 Iris 会话。板端无法在睡眠时先接收普通 RPC 再决定唤醒。

- 主机禁止挂起或 Gateway 持续通信时，实验固件延后硬件睡眠，保留在线待机；不能仅看睡眠页面就判定 MCU 已睡。
- 主机配合可以集成在 Gateway；自动空闲释放/按需重连仍是待实现方案。状态轮询、校时和自动重连都可能破坏空闲条件，不能只关闭一条 USB 连接就宣称完整流程可用。
- 不自动修改系统 USB 电源策略或停止其他客户端。获准验证时，记录主机策略、总线挂起/恢复、Device ID、Boot ID 及唤醒原因；退出恢复实验配置。
- 重连后确认设备身份和会话就绪再执行用户请求。连接失败时不盲目重发已发送的写操作。插拔/充电器/USB Serial-JTAG 唤醒需另验。

会话中的 USB 唤醒通信通过一次，但硬件睡眠期间的黑屏原因未定位，显示保持和恢复没有因此验收通过。

## 面板：AOD 与黑屏睡眠分开

该模组供应商给出的实验流程为：最终帧及 DMA 完成 → `FE 00` → `51 xx` 设置亮度 → `39` 进入 AOD；恢复时 `FE 00` → `38` 退出，再恢复用户亮度与画面。该轮使用 `xx=0x33` 表示约 20%，15 秒 DFS 在线空闲不进入 AOD。命令和亮度映射仅属于该面板，优先放在驱动/BSP，由同一显示所有者串行调用，处理部分失败和恢复。

- AOD 保持面板供电及画面；`28 → 10` 则是 Display OFF / Sleep IN 的黑屏路径，不能用来维持可见待机图案。
- 核对驱动是否附加 Deep Standby 或复位动作，不能把接口名当作实际命令序列。
- 会话讨论了可能的颜色量化，用户观察到橙色。实际模组的颜色、灰度文字可读性和唤醒恢复都需测；不能凭颜色宣称进入模式成功，也不把它固定称为黑白模式。
- 最后一帧、亮度恢复与 MCU 唤醒是独立验收项。看见待机图案、固件上传成功或一条唤醒日志均不足以证明完整流程。

## 触摸：轮询频率不等于扫描频率

该轮查阅的 CST9220 驱动只有 `D1 05` 休眠、`D1 09` 恢复接口，尚无可靠的低速扫描/手势唤醒协议依据。不要套其他 CST 型号命令，也不要假定休眠后仍能触摸唤醒。

降低 MCU 的 I²C 轮询频率仅减少读取；MCU light sleep 后不轮询，不代表 TP 内部扫描已降频。需要供应商确认低功耗扫描命令、进入/退出条件、INT 有效电平与锁存/清除、扫描周期和固件要求，再验证持续触摸、误唤醒及恢复首个输入。
