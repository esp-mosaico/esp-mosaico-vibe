# ESP-Mosaico App 功耗适配

目标是在保留所需显示、交互和连接能力的前提下降低整板功耗。40 MHz 是可验证的候选下限，不是任意 App 的默认保证；Vibe 的停止动画、15 秒超时、100 ms 检查周期都是案例，不自动推广为产品需求。

沿用消费工作区 AGENTS 的工程、Recovery、设备身份和 `mosaico.py` 操作规则。UI 改动使用原项目的真实框架验证交互；固件编译沿用工作区固定的 ESP-IDF 和构建入口。不为功耗适配迁移框架或更换固件架构。

## 先确定需要保留什么

检查当前板型、IDF/驱动版本、CPU/PSRAM/XIP 配置、显示提交路径及产品空闲需求，再选择本次要验证的模式。

| 产品需求 | 可评估方案 | 边界 |
| --- | --- | --- |
| 显示及通信持续运行，及时响应 USB/网络请求 | DFS + 按变化绘制 + Wi-Fi modem sleep | 仍有运行底耗，不能把低频当睡眠 |
| 页面静止，但状态需同步 | 停止不必要动画，保留事件或低频状态更新 | 不擅自变暗、换色、冻结状态栏或吞掉首次操作 |
| 较长时间不需要执行任务 | 评估 light sleep 和必要唤醒源 | 需要验证外设恢复、输入语义及通信要求 |

需要区分在线空闲、息屏页面与硬件睡眠，或接入 deep sleep 时，读取 [运行与睡眠状态](references/runtime-modes.md)。不要把“页面叫 sleep”或“画面停止”当成芯片已睡眠；deep sleep 唤醒重启，不能承诺保留 RAM 中的草稿或进程。

显式调用 light sleep 与 Wi-Fi 协同的自动 light sleep 是不同路径：Vibe 曾主动停止 Wi-Fi，不代表所有 light sleep 都必须放弃连接。自动睡眠可能配合 modem sleep 维持连接，仍需核对目标 SDK、驱动及 USB 支持；不要未经验证就打开。

涉及 USB 唤醒、AOD 或触摸低功耗扫描时，读取 [睡眠外设与验证边界](references/sleep-peripherals.md)。USB 总线挂起、面板 AOD 与 MCU light sleep 是三个独立状态，分别记录证据。历史案例与本次目标固件分开，不能把另一分支的实验当成当前 App 已具备的能力。

## DFS 与显示：先保证传输完成

做 DFS 或排查降频花屏时读取 [DFS 与显示传输](references/dfs-display.md)。

- 核对组件已有的 PM 支持，优先复用驱动/BSP，而不是每个 App 复制一套锁。CPU、MEM/SYS/APB 与外部 PSRAM 时钟不能混为一个频率。
- 如果当前显示路径需要应用侧 CPU_MAX 保护，覆盖显示命令、绘制及实际异步传输生命周期；提交返回不等于 DMA 完成。使用驱动提供的完成事件/fence/排空接口。
- 只有确认所有受保护事务和传输尾部结束才释放锁。排空失败时保留约束并可恢复，不为追求低频强制释放锁；采集错误而不是不断重试隐藏失败。
- 40 MHz 需要验证实际驻留、显示和并发稳定性。APB 最高频率锁不等于 CPU 最高频率锁，也不意味着 SPI 驱动一定有缺陷。
- 保留已验证的高频基线及回退方式。一次改一个条件；低频失败时先回退到已验证范围再定位，不凭瞬时 UI 读数宣布成功。

## 减少工作，而不是只改 MHz

- 区分业务空闲与调度器空闲。前者决定产品是否暂停动画，后者与 PM 锁决定是否允许降频；不需要等产品超时才启用 DFS。
- 无视觉变化不提交帧，使用框架已有脏区机制。动画保持产品需要的节奏；若允许空闲暂停，绘完最终帧后停止持续推进动画，保留输入恢复。
- 优先等通知/事件，必要轮询使用适合产品的周期。不要照抄 Vibe 的定时值或为了“看频率”增加常驻高频刷新。
- USB、Wi-Fi、电量仍在后台检测。只比较需要显示的值，变化才投影图标或格式化文本；RSSI 先转为显示档位，必要时评估滞回，避免边界抖动。
- 复用现有采样/事件，避免每个 UI tick 重新访问 Wi-Fi 驱动、I2C 或复制完整业务快照。缓存要覆盖页面进入/恢复、故障恢复和外部状态变化，不能形成旧图标。
- 对比停动画、高频固定与 DFS 三个条件，才能区分停绘和降频各自的收益。

## 屏幕颜色也是功耗条件

对于本板 OLED，发光面积、颜色和亮度都可能显著影响功耗；不要将该结论直接用于 LCD 背光屏。读取 [实测参考与限制](references/measurements.md) 中的颜色表后再选择对照。

- 比较同内容、同亮度下的背景颜色，或同颜色下的亮度。不要同时改卡片、文字、小人和软件增益，却声称结果只来自背景。
- 大面积白色可优先评估深灰/黑色方案，但产品设计需保持可读性。纯背景测流可保留其他像素不变；产品换肤需单独验证文字对比度和交互。
- 区分面板亮度设置、软件 RGB 增益、主题配色和熄屏，它们不是相同动作。20% 亮度不代表 20% 电流。
- 静止/无 SPI 传输不等于 OLED 停止发光；MCU 睡眠也不能消除保留显示画面的电流。

## 用可比较的数据验收

先保存固件/配置和测量条件，再做本次必要的对照，不要求每个 App 把所有历史实验重跑。

- 固定板号、供电入口/电压、USB 是否接主机或仅供电、充电状态、屏幕画面/亮度、Wi-Fi AP/信号/流量及测量窗口。供电电压不同优先比较功率，不直接比较 mA。
- USB 接线与充电会改变读数；日志、截图、镜像及监控本身也有负载。通过 Iris 保存证据后，在约定的安静测量窗口采样。
- 记录从启动到稳定的等待时间，并覆盖多个后台采样/无线唤醒周期，报告平均值及范围。稳定空闲阶段使用单独统计或累计计数差值，不把启动累计值当稳态。
- 同条件比较：固定高频/停动画 → DFS/停动画；需要归因时再分别试 Wi-Fi 完全不初始化、颜色/亮度或外设。仅未联网不等于 Wi-Fi 已关闭；拔屏不等于停用显示外设。
- 整板电池端电流不是 MCU 电流，不能把历史最小固件或芯片典型值直接当完整 App 的预算。
- 验收包括无花屏/死锁/传输错误、状态同步、输入恢复和所需通信/存储并发。截图不能证明无撕裂；模拟器不能验证时钟、电流或真实 DMA。

结果交付应说明：实际行为和保留能力、有效配置/固件标识、测量条件与数据、低频驻留证据、功能验证及局限。没有电流或硬件证据时明确标为待测，不承诺其他 App 复现相同 mA。
